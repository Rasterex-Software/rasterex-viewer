# Version 2.2.9 Change Notes

## Status

In progress. The local package version is 2.2.9 and Modern and Legacy
acceptance is complete.

## Summary

Expose native annotation editing and the Count workflow for SDK consumers.
The local test parent includes editable rectangle and Count samples and
checks whether Delete, Undo and Redo changed the annotation list.

## Added APIs

- `viewer.tools.getState()` reads native tools, navigation and SNAP state.
- `viewer.annotations.undo()`, `redo()` and `deleteSelected()` invoke the
  active document's native editing controls.
- `viewer.annotations.count.configure()` sets options for the next Count
  group. Start the Count tool through `viewer.tools.set()` and finish it with
  `count.finish()`. Subscribe to Canvas-initiated finishes with
  `count.onFinished(handler)` and call the returned function to unsubscribe.
- `count.insertPoint()` arms one insertion on the selected Count.
  `count.setPointMode({ enabled: true, guid })` enables repeated insertion.
  Pass `{ enabled: false }` to stop repeated insertion.
- `count.getItems(guid)` returns marker IDs, indices, native annotation
  coordinates and metadata. `count.setItemInfo(guid, itemId, info)` replaces
  one marker's flat metadata object. Values may be strings, finite numbers,
  booleans or null.
- The new request methods accept optional `requestId` and `timeoutMs`.

## Changed APIs

The local test parent confirms the target of a single Count insertion before
prompting for a click. It reports Canvas acknowledgements separately from
observed changes in the annotation list.

## Removed APIs

None. The existing fire-and-forget `annotations.setCountPointMode()` remains
available.

## Protocol Changes

The SDK wraps existing Canvas commands and replies. It correlates replies by
payload request ID and handles uncorrelated `countFinished` events separately.
The broker envelope, readiness handshake and protocol version remain the same.

## Compatibility Changes

The base Canvas compatibility matrix uses the new SDK version automatically.
Tool state and editing require `parentTools`. Count configuration and finish
require `countWorkflow`. Marker metadata requires `countItemInfo`. The
insertion methods use existing Canvas commands without a capability flag.
Feature availability depends on the connected Canvas build.

## Error Code Changes

Existing error codes cover missing capabilities, viewer readiness, command
failure and timeout. Canvas rejection details are preserved when supplied.
The SDK clears pending requests on disconnect and does not retry mutations
automatically.

## Diagnostics Changes

The local test parent logs correlated command results and reports whether its
refreshed annotation list changed.

## Framework Adapter Changes

The new APIs are available on the framework-independent viewer. No adapter
changes are required.

## Air-Gap and Security Impact

The SDK adds no external URLs, runtime dependencies, telemetry or CDN usage.
The new APIs use the existing iframe source and origin checks.

## Migration Notes

Existing integrations require no changes. Wait for `fileReady` before using
these APIs. Select an editable record in Canvas before deleting it or inserting
into a selected Count. Check the refreshed annotation list or marker list to
verify the effect of an acknowledged command.

## Documentation Notes for Docs Agents

The README describes API usage. The local Modern and Legacy test steps are in
`examples/annotation-tools/EDITING-COUNT.md`. The original signatures of
imported records are preserved. The editable examples belong to the local
test user.

## Test and Verification Notes

Live testing and user acceptance verified Delete and marker insertion in
Modern and Legacy. Live testing also verified Undo restores the rectangle,
Redo removes it again and insertion preserves existing Count markers.
`npm run check` covers synchronized versions, the build, automated tests,
source file limits and packed ESM and TypeScript declarations.

## Known Risks

Canvas may acknowledge an edit without changing a record. Native selection
requires an editable annotation owned by the current user. The imported
rectangle and Count samples are owned by the local test user for this reason.
Canvas can restore a deleted record asynchronously and may assign a new GUID.
