# Version 2.2.1 Change Notes

## Status

In progress

## Summary

Scope hosted evaluation to the Rasterex Sandbox and make SDK readiness reject
deterministically on timeout or cancellation.

## Added APIs

`ViewerReadyOptions` and `ready({ signal })` allow a host application to cancel
an in-flight readiness operation.

## Changed APIs

`viewer.ready()` performs Rasterex evaluation only when the configured
`viewerUrl` has the hosted Sandbox origin. Client-owned and self-hosted Canvas
URLs skip the hosted evaluation API.

`readyTimeoutMs` defaults to 60 seconds and rejects the complete readiness
lifecycle with `CANVAS_READY_TIMEOUT` when Canvas or hosted evaluation does not
complete. The timeout error includes `viewerUrl` and `timeoutMs` context.

## Removed APIs

None. No `licenseKey` option is added.

## Protocol Changes

No Canvas broker or Protocol V1 changes.

## Compatibility Changes

Self-hosted and air-gapped Canvas deployments no longer require network access
to `https://rxserver.rasterex.com/api/viewspace/evaluation` for SDK readiness.
The hosted Sandbox continues to require a valid backend-authoritative
evaluation.

## Error Code Changes

No new error codes. `CANVAS_READY_TIMEOUT` is now used for rejecting readiness
deadlines. `VIEWER_NOT_READY` is used when `ready({ signal })` is aborted.

## Diagnostics Changes

None.

## Framework Adapter Changes

None. The behavior is in the framework-independent core SDK.

## Air-Gap and Security Impact

The SDK no longer makes hosted evaluation requests for client-owned Canvas
URLs. The hosted evaluation API remains an external URL for Sandbox sessions.
No new runtime dependency, CDN, telemetry, or origin-validation behavior is
introduced.

Customer-owned Canvas deployments remain responsible for their own licensing or
entitlement enforcement. The SDK does not add an offline license format.

## Migration Notes

No code change is required for self-hosted users. Applications that previously
provided a self-hosted `viewerUrl` but also allowed the SDK to contact the
hosted evaluation service will no longer make that request.

Sandbox users retain the existing evaluation flow and error handling.

## Documentation Notes for Docs Agents

Update evaluation and deployment documentation to distinguish hosted Sandbox
evaluation from self-hosted Canvas licensing. State that the SDK identifies
Sandbox sessions by the hosted Sandbox origin, including URLs with paths or
query strings.

## Test and Verification Notes

Focused tests cover Sandbox-origin matching, custom/self-hosted URL bypass,
timeout rejection, timeout URL context, AbortSignal cancellation, and retry
after timeout. Run the build, full test suite, and source-line check.

## Known Risks

The current rule treats any URL on the hosted Sandbox origin as an evaluation
session. A future product decision may replace origin matching with an explicit
Sandbox preset or another deployment-level marker.
