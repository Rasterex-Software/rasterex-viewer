# Version 2.1.5 Change Notes

## Status

In progress

## Summary

Add a framework-independent view synchronization API for hosts with multiple Canvas viewer instances.

## Added APIs

`viewer.viewSync.configure({ groupId, instanceId, mode, enabled?, timeoutMs? })`, `viewer.viewSync.getSnapshot({ groupId, timeoutMs? })`, `viewer.viewSync.applySnapshot(snapshot, { timeoutMs? })`, `viewer.viewSync.apply(change, { pan?, zoom? })`, and `viewer.viewSync.on("changed" | "applied" | "failed", handler)`. Export their types, including `ViewSyncSnapshot`, `ViewSyncSnapshotRequest`, `ViewSyncSnapshotApplyOptions`, and `ViewSyncSnapshotApplied`.

## Changed APIs

`configure()` now accepts explicit `enabled: false` with a non-off mode and verifies that Canvas acknowledges the requested configuration. The SDK version reported in diagnostics and viewer information changes to `2.1.5`.

## Removed APIs

None.

## Protocol Changes

No Protocol V1 envelope change. The SDK maps the Canvas broker `{ type, payload }` view sync messages, including `getViewSyncSnapshot` / `viewSyncSnapshot` and `applyViewSyncSnapshot` / `viewSyncSnapshotApplied`. Live pan changes retain `coordinateMode: "delta" | "absolute"`.

## Compatibility Changes

Canvas must implement those broker messages for this API. The Canvas document does not specify a minimum Canvas version. The current broker `viewerReady` path does not expose dependable capability metadata, so this API does not gate on a `viewSync` capability. A deployment without a configuration response causes `configure()` to reject with the existing command timeout. This is an inference from the documented message flow; it is not a confirmed Canvas compatibility rule.

## Error Code Changes

No new codes. Invalid inputs, invalid Canvas results, and Canvas command failures use the existing SDK command error. Configuration and snapshot timeouts use `COMMAND_TIMEOUT` with `TIMEOUT_BASED` confidence; disconnect during a pending operation uses `VIEWER_NOT_READY`.

## Diagnostics Changes

The existing Canvas broker command and event diagnostics include the new message types.

## Framework Adapter Changes

None. React and other hosts use the core viewer API.

## Air-Gap and Security Impact

No new runtime URLs, dependencies, telemetry, or CDN usage. The existing broker validates origin and iframe source. Hosts with cross-origin Canvas should configure Canvas's documented `parentOrigin` URL parameter. Received `viewSyncChanged` payloads are checked against the configured group and instance before reaching application handlers.

## Migration Notes

After `ready()`, configure each viewer with a unique instance ID, shared group ID, desired mode, and `enabled: false`. Open documents and await their `fileReady` results. Call `getSnapshot()` on the source and `applySnapshot()` on every target; enable live sync only after every application succeeds. Relay `changed` events to sibling viewers using `apply()`. Unsubscribe and destroy viewers on host cleanup. Delta pan replay requires aligned initial views and compatible geometry.

## Documentation Notes for Docs Agents

The complete two-viewer React integration guide is `docs/live-npm/view-sync/react-host.md`. Document the four modes, host-owned routing, cross-origin `parentOrigin` and `referrerPolicy="origin"`, disabled configuration, document readiness, snapshot alignment, live relay, and document-change reset. Confirm Canvas echoes request IDs in configuration and snapshot results.

## Test and Verification Notes

Verified snapshot correlation, success and invalid-result handling, disabled configuration, acknowledgement mismatch, delta pan preservation, and disconnect cancellation with `npm run build`, `npm run check:source-lines`, and `node --test test/view-sync.test.mjs` (11 passing). Earlier evaluation verification: `npm run test:evaluation` (9 passing).

## Known Risks

The Canvas document does not define the minimum Canvas version. Snapshot alignment does not change page or rotation and can fail for incompatible geometry or constrained zoom/pan. Canvas may omit request IDs on live apply results. Sequence reset behavior across document changes remains a host responsibility.
