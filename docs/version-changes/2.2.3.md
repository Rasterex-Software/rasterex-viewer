# Version 2.2.3 Change Notes

## Status

In progress

## Summary

Release the npm SDK improvements for Sandbox evaluation boundaries, bounded
viewer readiness, promise-based comparison, package verification automation,
and npm package discoverability.

## Added APIs

None.

## Changed APIs

Evaluation runs only when `viewerUrl` uses the hosted Rasterex Sandbox origin.
Client-owned and self-hosted Canvas URLs skip hosted evaluation.

Viewer readiness defaults to a 60-second timeout. Hosts can override it with
`timeoutMs` and cancel it with an `AbortSignal`.

Normal comparison returns `Promise<ComparisonResult>` and resolves after the
payload-bearing `comparisonComplete` and following `progressEnd` events. It
rejects on Canvas comparison errors, timeout, disconnect, or invalid input.
`align(...)` and `save(...)` remain unchanged.

The npm package description and keywords now target the SDK's actual Rasterex,
CAD, DWG, DXF, DGN, IFC, PDF, document viewer, markup, measurement, takeoff,
and drawing comparison use cases.

The README first screen now leads with installation, quick start, supported
workflows, deployment choices, and links to documentation, examples, source,
and support.

## Removed APIs

None.

## Protocol Changes

No Canvas broker or Protocol V1 changes.

## Compatibility Changes

Self-hosted and air-gapped Canvas deployments do not require network access to
the hosted evaluation API for SDK readiness. Existing ESM package imports and
the public SDK API remain compatible.

## Error Code Changes

No new error codes. Readiness uses `CANVAS_READY_TIMEOUT` and
`VIEWER_NOT_READY`; compare timeouts use the existing `COMMAND_TIMEOUT` error.

## Diagnostics Changes

None.

## Framework Adapter Changes

None. The behavior remains in the framework-independent core SDK.

## Air-Gap and Security Impact

The SDK skips hosted evaluation for client-owned Canvas URLs. CI validates the
packed package, and release publishing uses npm trusted publishing through
GitHub Actions. No new runtime dependency, CDN reference, telemetry, or Canvas
application code is added.

## Migration Notes

Existing `await viewer.ready()` calls remain valid. Applications may optionally
provide a timeout or `AbortSignal`.

Applications using normal comparison can await the result:

```ts
const result = await viewer.compare.compare({
  fileA: "first.dwg",
  fileB: "second.dwg",
});
```

No migration is required for `align(...)` or `save(...)`.

## Test and Verification Notes

Run `npm run check`. This verifies version metadata, package metadata, build,
35 automated tests, source-line limits, packed-file contents, fresh ESM package
imports, and TypeScript declaration resolution.

## Known Risks

New npm metadata may take time to appear in npm search results. The npm package
name remains `@rasterex/viewer`; changing it would require a consumer migration.
