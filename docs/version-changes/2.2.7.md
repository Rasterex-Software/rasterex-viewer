# Version 2.2.7 Change Notes

## Status

Prepared locally on November 18, 2026; not published. The user confirmed
measurement inspection and vertex selection work in Modern and Legacy and
requested this version bump. No GitHub release action is part of this task.

## Summary

Add typed native measurement inspection and explicit vertex selection/clear
methods, plus controls in the local annotation test parent. Keep Legacy as the
default and preserve existing scale and calibration APIs.

## Added APIs

- `viewer.measurements.getInfo(options)` returns `Promise<MeasurementInfoResult>`.
  Required: zero-based active fileIndex/pageIndex and guid. Optional vertexIndex
  reads a chosen vertex without selecting or editing it.
- `viewer.measurements.selectVertex(options)` returns
  `Promise<MeasurementVertexSelectedResult>`. Required: fileIndex, pageIndex,
  guid and zero-based vertexIndex. Selects the native handle without moving it
  or starting a drag.
- `viewer.measurements.clearVertexSelection(options?)` returns
  `Promise<MeasurementVertexSelectionClearedResult>`. Releases parent-set native
  vertex state while retaining annotation selection.

All methods accept optional requestId and timeoutMs; timeout defaults to the
configured commandTimeoutMs. GUIDs normalize to uppercase without braces.
Request IDs must be nonblank, at most 256 characters and unique among pending
inspection/selection/clear calls. Indices must be nonnegative safe integers;
vertex indices are bounded below 1000. Invalid inputs fail before send.

Export request, response, measurement metadata, geometry, edge and vertex types
from the package entrypoint. Results preserve `coordinateSpace: 'nativeAnnotation'`.
Inspection supports the native metadata supplied by Canvas; the test parent
focuses on Distance, Area, Path and Rectangular Area. Optional calculations are
independent of metadata: geometry.available false includes a reason and is not
an inspection failure. Lengths use geometry.unit; areas use its square.

## Changed APIs

MeasurementsApiOptions gains an optional getCapabilities provider. Existing
scale/calibration calls remain available without it; new methods require the
appropriate advertised capability. RasterexViewer supplies its capability list.
Version metadata and SDK_VERSION now report 2.2.7. No other existing API changes.

## Removed APIs

None.

## Protocol Changes

Wrap existing Canvas commands/results only:

| Command | Reply | Required capability |
| --- | --- | --- |
| getMeasurementInfo | measurementInfo | measurementInfo |
| selectMeasurementVertex | measurementVertexSelected | nativeVertexSelection |
| clearMeasurementVertexSelection | measurementVertexSelectionCleared | nativeVertexSelection |

Use the existing `{type,payload}` envelope and payload requestId correlation.
Unrelated or uncorrelated replies are ignored; matching malformed replies fail.
No protocol version change, new Canvas handler, or compatibility alias is added.

## Compatibility Changes

No numeric minimum Canvas version is inferred. Require the advertised capability
for each method and fail before send when unavailable. Existing readiness and
compatible/degraded/incompatible behavior are unchanged. Wait for viewer.ready()
and document fileReady; file/page validity remains enforced by Canvas.

## Error Code Changes

No new codes or detection-confidence changes. Use VIEWER_NOT_READY before
readiness and on destruction; CAPABILITY_NOT_SUPPORTED for absent capabilities;
COMMAND_TIMEOUT for missing replies; UNKNOWN_COMMAND for invalid inputs/results,
send failures and native failures. Preserve native error text and result in
error context. Timeout does not establish whether selection changed. Do not
automatically retry selection/clear or send cleanup commands that could clear
newer native state. Pending listeners/timers are released on every terminal path.

## Diagnostics Changes

No new diagnostic events. SDK version reporting is 2.2.7.

## Framework Adapter Changes

None. The feature belongs to the framework-independent core. The local parent
uses the built SDK, explicit inspection/select/clear controls and stale-response
guards on viewer/file/page/selection/vertex changes and disclosure closure.
Displayed vertex numbers are one-based; SDK indices are zero-based.

## Air-Gap and Security Impact

No new runtime dependencies, hardcoded production URLs, external services,
telemetry or CDN references. Existing broker source/origin validation and mixed
content rules remain unchanged. The existing local sandbox testing configuration
remains confined to the example. Canvas and all scripts-folder files are untouched.

## Migration Notes

No changes required for existing integrations. After publication, install
@rasterex/viewer@2.2.7 to use the methods. Example:

```ts
const identity = { fileIndex: 0, pageIndex: 0, guid: '<annotation-guid>' };
const info = await viewer.measurements.getInfo(identity);
const vertex = await viewer.measurements.getInfo({ ...identity, vertexIndex: 0 });
await viewer.measurements.selectVertex({ ...identity, vertexIndex: 0 });
await viewer.measurements.clearVertexSelection();
```

Inspection does not require annotation selection and can inspect locked/read-only
records. Canvas rejects prohibited selections and active native gestures. Points
are saved native annotation coordinates, not PDF or iframe CSS coordinates;
never feed them into PDF creation/conversion APIs as PDF points.

## Documentation Notes for Docs Agents

Document the three methods, exported types, required capabilities, correlation,

optional calculation availability and nativeAnnotation coordinates. Link the
local parent's Measurement / vertex inspection panel and

extraction, vertex movement, snapping, annotation import or a rotation fix.
