# Version 2.2.6 Change Notes

## Status

Prepared locally on November 17, 2026; not published. The user confirmed the
local Modern/Legacy annotation test works and requested this version bump.
This carries forward the existing unpublished changes documented under 2.2.5.

## Summary

Fix evaluation readiness retries and response body timeout/cancellation. Add an
optional internal evaluation bypass to the public npm package without backend
changes, while preserving Canvas readiness.

Add explicit Modern/Legacy annotation appearance switching through the existing
Canvas broker. Legacy remains the default; mounting and readiness send no
appearance command. Preserve Canvas-advertised capabilities for feature discovery.

## Added APIs

`viewer.styles.setMeasurementAppearance({mode, requestId?, timeoutMs?})` returns
`Promise<MeasurementAppearanceResult>`. Mode is `legacy` or `modern`. Request IDs
are generated when omitted; explicit IDs must be nonblank strings up to 256
characters and unique among pending appearance calls. Timeouts default to
`commandTimeoutMs` and must be positive integers within the browser timer range.
Only the matching `measurementAppearanceChanged` response settles a request;
success requires a boolean success flag and the requested mode. Canvas failures
preserve their native error/result in the SDK error context. Disconnect/destroy,
send failures and timeouts release pending appearance listeners and timers.

New root type exports: `MeasurementAppearanceMode`,
`SetMeasurementAppearanceOptions`, `MeasurementAppearanceResult`.
`StylesApiOptions.getCapabilities?` supplies advertised capability names for
direct domain construction. Existing styles APIs do not require the provider;
the new appearance method requires its `measurementAppearance` capability.
`StylesApi.disconnect()` releases pending appearance requests.

Optional `evaluation.internalBypassKey?: string` on `RasterexViewerOptions`
through the exported `EvaluationRegistrationOptions` interface. An exact match
against the embedded internal key skips hosted evaluation activation,
registration, validation, and token storage access. Missing, empty, incorrect,
or whitespace-modified values retain normal evaluation behavior. Existing
stored tokens, including expired tokens, are untouched when bypassing.

## Changed APIs

`viewer.getInfo().capabilities` now retains valid capability names from plain
Canvas `viewerReady.payload.capabilities` alongside the existing `iframe` and
`document.open` baseline. The public type is `readonly string[] | null`, allowing
current and future Canvas names without changing Protocol V1's capability type.
The messaging session subscribes before starting, so early ready events are
retained. Lists must contain only strings; absent/malformed lists contribute no
capabilities. Duplicate names are removed and the retained arrays are frozen.
Source/origin validation occurs before capture. Session destruction clears the
retained Canvas list. Legacy viewers still become ready, but appearance switching
fails explicitly when support is not advertised.

`viewer.ready()` ignores evaluation callbacks belonging to settled readiness
attempts. Retrying after an abort or timeout no longer lets an earlier callback
leave the current promise pending or cause a false `CANVAS_READY_TIMEOUT`.

The evaluation request's existing 10-second timeout and abort controller remain
active through JSON response body consumption. Viewer destruction aborts that
work and rejects pending readiness with the existing lifecycle error.
Validation body network failures and timeouts follow the existing transient
retry policy; malformed JSON is not retried. Activation is not retried.
Permanent HTTP failures preserve their status and are not retried.

`SDK_VERSION`, `package.json`, and both root lockfile versions report `2.2.6`.

## Removed APIs

None.

## Protocol Changes

No new Canvas commands, callbacks, payloads, events, capabilities, or Protocol V1
changes. The SDK wraps existing `setMeasurementAppearance` /
`measurementAppearanceChanged` messages with `{type,payload}` and
`{mode,requestId}` / `{success,mode,requestId,error?}` payloads. The existing
`measurementAppearance` capability is required. No protocol version bump is required.

## Compatibility Changes

No changes to minimum Canvas/SDK requirements, the compatibility matrix, or
compatible/degraded/incompatible behavior. The internal bypass still requires
Canvas readiness and existing compatibility checks.

Plain Canvas readiness retains its existing degraded status; capturing advertised
capabilities does not imply Protocol V1 compatibility or invent a Canvas version.
The new appearance method requires a Canvas deployment advertising
`measurementAppearance`; older deployments reject before send. No numeric minimum
Canvas version is inferred. Fresh viewers retain Legacy, and explicit Modern
selection lasts across documents within the same Canvas session.

## Error Code Changes

No new codes or detection-confidence changes. Appearance switching uses
`VIEWER_NOT_READY` before readiness or on disconnect, `CAPABILITY_NOT_SUPPORTED`
when support is absent, `COMMAND_TIMEOUT` for missing replies, and the existing
domain-command `UNKNOWN_COMMAND` classification for invalid input/results, send
failures and explicit native failure. Native error text/result remains available
in the error context. A timeout does not confirm the resulting Canvas mode.
Readiness retries report the
current attempt's outcome. Body timeouts use existing evaluation failure codes;
destroyed readiness retains `VIEWER_NOT_READY`.

## Diagnostics Changes

No new events. SDK version information reports `2.2.6`. The internal key is not
included in diagnostics, viewer info, evaluation requests, or Canvas messages.

## Framework Adapter Changes

None. The option belongs to the framework-independent core.

Appearance switching is also framework-independent. A local browser example at
`examples/measurement-appearance.html` imports the built SDK, accepts a Canvas
URL, configures parentOrigin, waits for readiness and provides a Legacy/Modern
selector. It performs no automatic appearance switch.

## Air-Gap and Security Impact

No new external URLs, runtime dependencies, telemetry, CDN references, origin
validation changes, or mixed-content changes. Without a valid bypass key,
Sandbox evaluation remains required. Self-hosted Canvas continues to skip
hosted evaluation.

The bypass key is intentionally embedded in the public package and can be
extracted and reused. The user explicitly accepted this exposure on 2026-10-23.
This is a convenience switch, not an authentication or licensing boundary.
It needs no backend change, does not alter Canvas-side licensing, and does not
make hosted Sandbox available offline. Request timeout/cancellation now covers
response body consumption.

## Migration Notes

Install `@rasterex/viewer@2.2.6` after publication. Existing integrations need no
code changes. To opt into Modern, await `viewer.ready()`, then call
`await viewer.styles.setMeasurementAppearance({mode:'modern'})`; restore Legacy
with the same method and `mode:'legacy'`. Continue using existing tools/annotation
events. Modern is a presentation preset, not a new annotation storage format.
Consumers explicitly assigning getInfo().capabilities to the old closed Protocol
V1 capability union should accept readonly strings and test the relevant name.
Internal integrations may opt in with
`evaluation: { internalBypassKey: "<internal-bypass-key>" }`; continue calling
`mount()` and awaiting `ready()`. Key rotation or removal requires a package
change and corresponding migration notes. Its implementation is maintained in
`src/evaluation/requiresHostedEvaluation.ts`.

## Documentation Notes for Docs Agents

- Document the new styles method, exported types, required capability, correlated
  promise, errors, and Legacy default. Do not show an automatic Modern constructor
  option or invent a new broker message. Existing tools remain the creation API.
- Explain that capabilities now include advertised Canvas strings, including
  unknown future names, while plain-ready compatibility remains degraded.
- Link the local HTTP example and explain its configurable Canvas URL and
  parentOrigin. Keep PDF export/rendering acceptance separate from broker tests.
- Document `evaluation.internalBypassKey`, exact matching, extractability, and
  the absence of backend changes. Do not describe it as secure authentication.
- Explain that bypassing skips evaluation storage/network access and leaves
  existing tokens untouched, while preserving Canvas readiness, compatibility,
  timeout, and cancellation.
- Describe readiness retries after abort/timeout and the request timeout's
  coverage of response body consumption, including cancellation on destruction.
- README includes the option and its intended internal use. Self-hosted
  deployments continue to require no hosted evaluation or bypass key.

revoked without a package change or a future backend entitlement mechanism.
Validation remains fail closed without the bypass. This release has not been
published. The Stage 2 local parent exercised the real sandbox Rasterex backend;
its command-level results and incomplete native gesture acceptance are recorded
separately from unit/package verification.

builds the current SDK and starts a loopback Vite parent importing
`../../dist/index.js`, plus a loopback proxy for the separately running local

added in this stage.
